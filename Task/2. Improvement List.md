# Improvement List

## Tujuan

Daftar perbaikan ini dibuat untuk meningkatkan kualitas kode, stabilitas, dan kesiapan proyek SCM App agar lebih sesuai dengan standar industri.

## 1. Tambahkan test coverage nyata

- Buat unit test untuk `HasCodeGenerator`, `Blameable`/approval logic, dan model relation penting.
- Buat feature test untuk Filament resource CRUD, role/permission, dan login flow.
- Aktifkan test DB in-memory di `phpunit.xml` (`sqlite`/`:memory:`) agar test stabil dan terisolasi.

## 2. Terapkan static analysis dan code style

- Pasang dan konfigurasikan `phpstan` / `psalm` / `larastan`.
- Gunakan `laravel/pint` untuk formatting konsisten.
- Tambahkan command `composer test` / `composer lint` untuk memudahkan pemeriksaan.

## 3. Tambahkan pipeline CI

- Buat GitHub Actions / GitLab CI / Azure Pipelines.
- Workflow minimal:
    - `composer install`
    - `npm install`
    - `php artisan test` / `./vendor/bin/phpunit`
    - `php artisan pint`
    - static analysis

## 4. Perbaiki manajemen dependency JavaScript

- Tambahkan lockfile JS: `package-lock.json` atau `pnpm-lock.yaml`.
- Pastikan `package.json` dan lockfile selalu sync.
- Tambahkan script `npm test` atau `npm lint` jika perlu.

## 5. Perbaiki arsitektur kode domain

- Pindahkan logika generate kode otomatis dari trait global ke service / repository khusus.
- Hindari query `DB::table($tableName)` dengan nama string di trait.
- Gunakan observer / event listener untuk audit/blameable daripada `Auth::check()` langsung di model.

## 6. Review resource Filament dan naming

- Perbaiki label yang tidak konsisten seperti `navigationLabel = ' List of Customer'`.
- Pastikan semua resource menggunakan naming singular/plural konsisten.
- Review `getRecordRouteBindingEloquentQuery()` dan global scope yang dihapus.

## 7. Auditing dan approval flow

- Pastikan `HasApproval`/`ApprovalLog` memakai hubungan dan status yang jelas.
- Buat test untuk skenario approval, reject, dan draft.

## 8. Dokumentasi proyek

- Perkuat `README.md` dengan:
    - cara menjalankan test
    - cara setup Filament Shield / role admin
    - arsitektur singkat
    - standar coding/contribution
- Tambahkan `CONTRIBUTING.md` jika ada tim.

## 9. Konfigurasi environment yang lebih aman

- Pastikan `.env` tidak ter-commit.
- Tambahkan `.env.example` yang bersih dan lengkap.
- Terapkan `.gitignore` untuk file build dan IDE, cek lagi bila ada artefak baru.

## 10. Pastikan codebase bebas “debug artifact”

- Cari dan hapus `dd()`, `dump()`, `var_dump()`, `exit()`, `die()`.
- Pastikan tidak ada log debugging di kode produksi.

## 11. Struktur file dan modularitas

- Evaluasi apakah `app/Blameable.php`, `app/HasApproval.php`, `app/HasCodeGenerator.php` lebih tepat jadi service/Action.
- Pertimbangkan folder `Services`, `Actions`, atau `Jobs` untuk logika bisnis non-model.

## 12. Setup lingkungan dev

- Buat dokumentasi singkat untuk:
    - `composer install`
    - `npm install`
    - `php artisan migrate`
    - `php artisan storage:link`
    - `php artisan serve`

## Prioritas cepat

1. Test coverage + `phpunit.xml`
2. CI pipeline
3. Static analysis / `pint`
4. Perbaikan `HasCodeGenerator` / audit logic
5. Dokumentasi `README`
